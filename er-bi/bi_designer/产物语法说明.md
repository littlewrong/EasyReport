# bi_designer GoView 前端说明

本文面向 EasyReport 中 `er-bi/bi_designer` 这个 GoView 派生前端，重点说明本项目的启动、目录、接口、画布 JSON 产物结构，以及后续如何快速新增组件和生成可导入示例文件。

## 1. 项目定位

`bi_designer` 是一个基于 GoView 的大屏可视化设计器前端。

主要能力：

- 在工作台中拖拽组件，配置画布、图层、图表样式、静态数据、接口数据和事件。
- 将当前大屏序列化为 JSON，保存到后端 `bi_project.content` 一类字段中。
- 支持 JSON 导入、导出、在线编辑、预览、发布。
- 支持 ECharts、VChart、Naive UI、自定义静态组件、图片、图标和装饰组件。

当前分支已经接入 EasyReport 后端接口，不是原始 GoView 纯前端 Demo。

## 4. 核心路由

路由枚举在 `src/enums/pageEnum.ts`。

| 页面 | 路径 | 说明 |
| --- | --- | --- |
| 项目首页 | `/project` | 大屏项目工作台入口 |
| 设计器 | `/chart/home/:id` | 按项目 id 加载并编辑大屏 |
| 预览 | `/chart/preview/:id` | 从 `sessionStorage` 读取当前大屏并预览 |
| JSON 编辑器 | `/chart/edit/:id` | 新窗口在线编辑 JSON，并回写源设计器 |

设计器进入逻辑：

1. `/chart/home/:id` 读取路由 id。
2. 调用 `getProjectDataApi(id)`。
3. 如果返回 `content`，使用 `JSONParse(content)` 转对象。
4. 调用 `useSync().updateComponent(projectData, true)` 还原画布。

## 5. 后端接口

接口定义在 `src/api/path/index.ts`。

接口前缀：

```ts
const PREFIX = `${API_BASE}/bi/project`
```

默认 `API_BASE=/biapi`，所以浏览器请求形如：

```text
/biapi/bi/project/list
/biapi/bi/project/getData
/biapi/bi/project/save/data
```

主要接口：

| 方法 | 地址 | 说明 |
| --- | --- | --- |
| POST | `/bi/project/create` | 新建大屏 |
| GET | `/bi/project/list` | 大屏分页列表 |
| GET | `/bi/project/getData?projectId=1` | 获取单个大屏内容 |
| POST | `/bi/project/save/data` | 保存大屏 JSON 和封面 |
| POST | `/bi/project/edit` | 编辑名称、备注、封面 |
| POST | `/bi/project/publish` | 发布 / 取消发布 |
| DELETE | `/bi/project/{id}` | 删除大屏 |

保存接口参数：

```json
{
  "projectId": 1,
  "content": "{...}",
  "indexImage": "data:image/png;base64,..."
}
```

注意：`content` 是字符串，内容是 `chartEditStore.getStorageInfo()` 序列化后的 JSON。

## 6. 大屏 JSON 产物结构

导入、导出、保存、在线编辑都围绕同一个结构：

```ts
{
  editCanvasConfig: EditCanvasConfigType,
  requestGlobalConfig: RequestGlobalConfigType,
  componentList: Array<CreateComponentType | CreateComponentGroupType>
}
```

导出入口：

- `src/views/chart/ContentEdit/components/EditTools/utils/index.ts`
- 调用 `chartEditStore.getStorageInfo()`
- 使用 `JSONStringify()` 下载 JSON

导入入口：

- `src/views/chart/ContentEdit/components/EditTools/hooks/useFile.hooks.ts`
- 读取 JSON 后调用 `updateComponent(fileData, isReplace, true)`

在线编辑器入口：

- `src/views/edit/index.vue`
- 从 `sessionStorage.GO_CHART_STORAGE_LIST` 初始化。
- `Ctrl + S` 或保存按钮触发 `SaveJSON` 事件，源工作台用 `updateComponent()` 覆盖刷新。

### 6.1 editCanvasConfig

画布配置，存储大屏尺寸、背景、滤镜、主题和预览适配方式。

常用字段：

| 字段 | 说明 |
| --- | --- |
| `projectName` | 大屏名称 |
| `width` / `height` | 画布尺寸，默认 `1920 * 1080` |
| `background` | 背景色 |
| `backgroundImage` | 背景图，可为 URL 或 base64 |
| `selectColor` | 是否使用纯色背景 |
| `chartThemeColor` | ECharts 主题色名称，默认 `dark` |
| `chartThemeSetting` | ECharts 全局主题配置 |
| `vChartThemeName` | VChart 主题名，默认 `vScreenVolcanoBlue` |
| `previewScaleType` | 预览适配方式 |
| `filterShow` / `opacity` / `saturate` / `contrast` / `brightness` / `hueRotate` | 画布滤镜 |
| `rotateZ` / `rotateX` / `rotateY` / `skewX` / `skewY` / `blendMode` | 画布变换 / 混合模式 |

默认值来源：

- `src/store/modules/chartEditStore/chartEditStore.ts`
- `src/settings/designSetting.ts`
- `src/settings/chartThemes/index.ts`

### 6.2 requestGlobalConfig

全局请求配置，给所有组件请求复用。

常用字段：

| 字段 | 说明 |
| --- | --- |
| `requestOriginUrl` | 组件接口公共前缀，可为空 |
| `requestInterval` | 默认轮询间隔，默认 `30` |
| `requestIntervalUnit` | 默认轮询单位：`second` / `minute` / `hour` / `day` |
| `requestParams.Header` | 全局请求头 |
| `requestParams.Params` | 全局 query 参数 |
| `requestParams.Body` | 全局 body 模板 |
| `requestDataPond` | 公共数据池列表 |

请求实现：

- 普通组件接口请求：`src/hooks/useChartDataFetch.hook.ts`
- 数据池请求：`src/hooks/useChartDataPondFetch.hook.ts`
- 请求组装：`src/api/http.ts` 的 `customizeHttp()`

### 6.3 componentList

组件数组，决定画布上所有图层。

每个组件基本结构：

| 字段 | 说明 |
| --- | --- |
| `id` | 组件实例 id，建议形如 `id_xxx`，导入新增时可自动换 id |
| `isGroup` | 是否分组 |
| `key` | 组件 key，例如 `BarCommon` |
| `chartConfig` | 组件元信息，用于动态注册和重新实例化 |
| `attr` | 坐标、尺寸、层级 |
| `styles` | 滤镜、动画、透明度、旋转等通用样式 |
| `status` | `lock` / `hide` |
| `request` | 当前组件的数据请求配置 |
| `filter` | 请求数据过滤函数体字符串 |
| `events` | 基础事件、高级生命周期、组件交互事件 |
| `option` | 组件自身配置。图表组件一般是 ECharts option 或 VChart 业务配置 |
| `groupList` | 分组子组件，仅 `isGroup=true` 时存在 |

组件被导入时不会直接使用 JSON 对象渲染，而是：

1. 根据 `chartConfig.package/category/key` 动态 import 对应 `config.ts`。
2. new 出组件默认实例。
3. 用 JSON 中的字段覆盖默认实例。

因此生成示例文件时，`chartConfig` 必须能定位到真实组件。

## 7. 组件包与动态注册

组件总入口：

- `src/packages/index.ts`

组件包枚举：

```ts
Charts        ECharts 图表
VChart        VChart 图表
Tables        表格 / 列表
Informations 文字、输入、图片、视频、iframe 等信息组件
Photos        用户图片组件
Icons         图标组件
Decorates     边框、装饰、数字、时间、3D 等组件
```

组件目录标准形态：

```text
src/packages/components/{Package}/{Category}/{Key}/
  index.ts    组件元信息 ConfigType
  config.ts   组件实例类，继承 PublicConfigClass
  index.vue   画布渲染组件
  config.vue  右侧属性配置面板
  data.json   可选，默认静态数据
```

以 ECharts 柱状图为例：

```text
src/packages/components/Charts/Bars/BarCommon/
  index.ts
  config.ts
  index.vue
  config.vue
  data.json
```

`index.ts` 暴露组件元信息：

```ts
export const BarCommonConfig = {
  key: 'BarCommon',
  chartKey: 'VBarCommon',
  conKey: 'VCBarCommon',
  title: '柱状图',
  category: ChatCategoryEnum.BAR,
  categoryName: ChatCategoryEnumName.BAR,
  package: PackagesCategoryEnum.CHARTS,
  chartFrame: ChartFrameEnum.ECHARTS,
  image: 'bar_x.png'
}
```

`config.ts` 负责生成组件实例：

```ts
export default class Config extends PublicConfigClass implements CreateComponentType {
  public key = BarCommonConfig.key
  public chartConfig = cloneDeep(BarCommonConfig)
  public option = echartOptionProfixHandle(option, includes)
}
```

新增组件时，需要同时把组件 Config 加入对应分类的 `index.ts`。例如：

```ts
// src/packages/components/Charts/Bars/index.ts
import { MyBarConfig } from './MyBar/index'

export default [BarCommonConfig, MyBarConfig]
```

## 8. 生成可导入示例文件

示例文件本质就是保存接口中的 `content` 内容，即 `ChartEditStorage` JSON。

最小生成规则：

1. 顶层必须有 `editCanvasConfig`、`requestGlobalConfig`、`componentList`。
2. `componentList[*].chartConfig` 必须对应真实组件。
3. ECharts 组件常用数据格式为 `option.dataset.dimensions/source`。
4. VChart 组件常用数据格式为 `option.dataset.values`，字段名需匹配 `xField/yField/seriesField`。
5. 导入新增模式会重生成 id；覆盖模式会替换当前画布。
6. 如果手写 JSON，建议先用设计器拖出一个同类组件并导出，再按导出结构改字段。

## 9. 接口数据示例规则

组件 `request.requestDataType`：

```ts
0 = 静态数据
1 = AJAX 请求
2 = 数据池
```

普通 AJAX 示例：

```json
{
  "requestDataType": 1,
  "requestHttpType": "get",
  "requestUrl": "/mock/chartData",
  "requestInterval": 30,
  "requestIntervalUnit": "second",
  "requestContentType": 0,
  "requestParamsBodyType": "none",
  "requestSQLContent": {
    "sql": "select * from  where"
  },
  "requestParams": {
    "Body": {
      "form-data": {},
      "x-www-form-urlencoded": {},
      "json": "",
      "xml": ""
    },
    "Header": {},
    "Params": {}
  }
}
```

如果组件配置了 `filter`，它是函数体字符串，入参固定为：

```ts
data // 接口返回的 res.data
res  // axios 完整响应对象
```

示例：

```js
return {
  dimensions: ['name', 'value'],
  source: data.rows
}
```

注意：`filter` 内部通过 `new Function('data', 'res', filter)` 执行，只适合可信配置。

请求参数中支持 `javascript:` 前缀动态表达式，解析逻辑在 `src/api/http.ts` 的 `translateStr()`。

示例：

```json
{
  "Params": {
    "date": "javascript:return new Date().toISOString().slice(0, 10)"
  }
}
```

## 10. 新增组件开发流程

推荐流程：

1. 在对应包下复制一个相近组件目录。
2. 修改目录名、`key`、`chartKey`、`conKey`、`title`、预览图。
3. 修改 `config.ts` 的默认 `option` 和默认数据。
4. 修改 `index.vue` 的渲染逻辑。
5. 修改 `config.vue` 的右侧配置面板。
6. 在父级分类 `index.ts` 中导出新组件 Config。
7. 启动设计器，确认左侧组件面板能看到新组件。
8. 拖到画布，导出 JSON，作为后续示例文件模板。

命名约定：

| 字段 | 约定 |
| --- | --- |
| `key` | 组件目录名，例如 `BarCommon` |
| `chartKey` | 画布组件注册名，通常加 `V` 前缀 |
| `conKey` | 配置面板组件注册名，通常加 `VC` 前缀 |
| `package` | 必须是 `PackagesCategoryEnum` 中的值 |
| `category` | 对应组件包内部分类，例如 `Bars` / `Pies` / `Texts` |

动态 import 路径要求：

```ts
./components/${packageName}/${categoryName}/${keyName}/config.ts
```

所以 `package/category/key` 必须和目录完全一致。

## 12. 注意事项

- 不要直接把手写 JSON 塞进 `componentList` 后渲染；应走 `updateComponent()`，它会重新实例化组件并注册 Vue 组件。
- `content` 落库前必须是字符串，推荐使用项目内 `JSONStringify()`，它会处理函数和 `undefined`。
- `JSONParse()` 只会对 `formatter` 这类函数字段做有限还原，事件和过滤器一般保持字符串。
- 分组组件 `isGroup=true` 时，外层是 `PublicGroupConfigClass` 结构，子组件放在 `groupList`，子组件坐标是相对分组的坐标。
- ECharts 组件更新时多数依赖 `dataset`，字段数量变化时部分组件会根据 `dimensions` 自动修正 `series`。
- VChart 组件会先保存业务配置，再通过 `src/components/GoVChart/transformProps` 转成最终 spec。
- 图片、图标类组件可能使用 `redirectComponent`，即元信息在图片/图标包里，但实例使用另一个真实组件。
- 生产环境 `base=/bidesigner/`，如果刷新 404，需要 nginx 对该子路径做 SPA fallback。
